# Общий механизм складских операций

Механизм применяется ко всем сделкам. Реальные документы автоматически не перепроводятся.

## Операции

| Действие | Склад | Финансовые документы |
|---|---|---|
| Списать на проект | Прямой расход выбранных материалов из места хранения; бригада не обязательна | Связанная себестоимость проекта. Обычное признание НЗП сохраняется |
| Приход и расход на проект | Связанные поступление и расход конкретной поставки; старые партии не подменяют прямую поставку | Обязательство перед поставщиком и затраты проекта. Платёж не создаётся |
| Отгрузить покупателю | Расход проданного количества по FIFO без участия бригады | Связанная реализация по продажной цене и точная себестоимость отгруженных товаров |

Форма содержит несколько позиций, дату и документ-основание. Цена продажи отличается от цены закупки. Ставка НДС и право на вычет поступления указываются явно; внутреннее списание не формирует повторный вычет.

В карточке каждой сделки раздельно видны закупки с НДС, распределённые оплаты поставщикам, оставшиеся партии на складе/у бригады и списанная себестоимость. Смешанное распределение оплаты одной накладной по нескольким проектам отмечается для сверки вместо назначения полной оплаты одному проекту. Состав сметы автоматически не выдумывается из закупки.

Документ можно открыть целиком и отменить с резервной копией в открытом периоде. Отдельное удаление реализации, расхода или складской строки запрещено. Для оплаченного поступления сначала снимается связь оплаты; для зависимых движений сначала исправляются зависимости. Денежные операции при отмене сохраняются.

## Финансовые границы

Точная себестоимость продажи признаётся по отгруженным позициям; цена договора не используется для пропорционального списания стоимости этих товаров. Для смешанного монтажа и продажи без заданного разделения выручки частичный результат явно требует сверки. Обычные монтажные операции и их НЗП сохраняют прежние правила. Механизм не создаёт отдельные регистры возвратов покупателя, налоговые декларации или предположительные платежи.

## Проверки

- 961 тест Node: расчёты, исходные связи, резервы других проектов, дробные количества, защита повторов, даты, роли, отмена и старые сценарии.
- Нативные формы Chromium на 375/1440: продажа нескольких товаров без бригады, прямое списание, поступление с расходом, НДС, отмена, оплата, сохранение черновика при конфликте, закрытый период и смена пользователя.
- Старый полный цикл двух компаний и двух месяцев прошёл без изменения контрольных сумм.
- PostgreSQL 16.15: восемь SQL-наборов, защищённые RPC, откат двух хранилищ, полномочия, закрытые периоды и повтор FIFO. Проверены семь действительных результатов модели, включая кириллический ключ сделки и дробную переданную партию.
- Исправлены три подтверждённые интеграционные находки независимой проверки: физические источники FIFO на сервере, обходы через старые удаления, отсутствовавший складской контекст в колонке «Факт».

Последние результаты Chromium/WebKit и точного дерева публикации доступны в проверках pull request соответствующей версии. Локально Chromium не выдаётся за WebKit. Тестовые документы изолированы от рабочих данных.
