# ARBAT FINANCE — контрольный отчёт безопасности, 18.10.2026

## Подтверждено автоматическими проверками и чтением метаданных Supabase

- Финансовый и складской shared-state защищены проверкой разрешённой роли и действующей auth.sessions через RLS и update_shared_state; ревизии проверяются на конфликт.
- Вызовы admin_people_list, admin_staff_list, admin_set_staff, claim_staff_access, my_payroll и set_finance_period_status содержат проверку действительности сессии.
- Журнал staff_activity имеет активный триггер, запрещающий UPDATE/DELETE.
- Состояния финансов и склада имеют активные триггеры аудита по ревизиям.
- Изолированная проверка резервной копии с SHA-256 покрыта тестами на синтетических данных.
- Все публичные таблицы, перечисленные в базе, имеют RLS.

## Не подтверждено / критично для окончательной приёмки

1. **Нельзя подтвердить отзыв сессии реального пользователя без безопасной тестовой учётной записи.** По результату чтения базы сейчас нет отключённых сотрудников, всего 1 запись staff_access. Не отключать действующего пользователя ради теста.
2. **Защита от скомпрометированных паролей отключена в Supabase Auth** (Security Advisor). Требуется включить в настройках проекта, затем повторно запустить Advisor. Документация: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
3. **Security Advisor предупреждает об открытом EXECUTE на 8 SECURITY DEFINER RPC.** Выполнение авторизованным пользователем само по себе ожидаемо для функций приложения, но каждой функции нужны role/session проверки и негативные проверки на реальном изолированном пользователе. Помощь: https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
4. **Закрытие финансового периода** защищено серверным триггером, но на отдельной тестовой базе не проверены все исторические типы документов, записи сторно и полнота охвата.
5. **Резервирование и восстановление в отдельном экземпляре Supabase** не выполнялись; тесты подтверждают только чтение и контрольную сумму JSON-файла.
6. **Сквозной сценарий** от создания сделки через закупки, склад, акты, расходы, зарплаты и расчёт прибыли на отдельной тестовой базе всё ещё необходим.
7. RLS таблицы auth_request_limits без политики — ожидаемое намеренное ограничение: доступ через service_role, не напрямую пользователям.

## Правило приёмки

Не объявлять систему полностью проверенной, пока вышеперечисленные пункты не подтверждены в изолированной среде. Не запускать стресс-тесты и тестовые документы на действующих финансовых записях. Сверять денежные суммы в копейках, с расхождением не более 0,01 ₽.

## Изменения настоящего пакета

Добавлен regression gate для семи защищённых RPC, блокировки закрытого периода и неизменяемого журнала аудита. Данные пользователей и документы не изменялись.
