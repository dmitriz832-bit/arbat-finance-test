# ARBAT FINANCE: контрольная точка приёмки 18.10.2026

Проверка подключения Supabase без изменения клиентских данных.

Подключён только один проект: ARBAT FINANCE (prod). Отдельной staging-базы нет.

## Подтверждено запросами к производственной базе

- finance_state: ревизия 66, JSON-объект.
- warehouse_state: ревизия 17, JSON-объект.
- У семи прикладных privileged RPC вызов от anon запрещён; разрешён authenticated при прохождении проверок в теле функций.
- Семь функций имеют признаки наличия серверного session-check.
- Проверка защитных триггеров проводилась ранее: staff_activity_immutable, finance_state_update_audit, warehouse_state_update_audit.

## Граница проверки

Тестировать UPDATE/ROLLBACK над производственной базой ради приёмки нельзя. Здесь выполнены только SELECT-запросы к метаданным и номерам ревизий. Само присутствие проверки в SQL-функциях не доказывает корректность отказа после реального завершения сессии. Для этого требуется отдельная тестовая учётная запись и отдельная staging-база.

## Условия перехода к статусу «принято»

1. Воспроизвести операции записи, конфликт ревизий и восстановление из backup на отдельном экземпляре.
2. Проверить прекращение чтения и записи со старым JWT после удаления тестовой сессии.
3. Включить leaked-password protection в Supabase Auth и подтвердить отсутствие предупреждения.
4. Выполнить сквозной браузерный тест на staging через создание и закрытие реальных документов.
5. Сверить итоговые ОПиУ, ДДС, долги и FIFO с независимой ручной моделью.
