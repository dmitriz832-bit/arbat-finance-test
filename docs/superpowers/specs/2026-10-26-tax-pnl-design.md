# Помесячные налоги для управленческого ОПиУ

Проверка my.fintablo.ru разрешена пользователем. Сам модуль налогов закрыт тарифом, но https://help.fintablo.ru/article/3453 подтверждает: бухгалтер вносит начисления налога на доход/прибыль по месяцам; квартальная корректировка распределяет итог пропорционально предварительным начислениям. Оплата и НДС не должны повторно уменьшать прибыль.

Решение исполнителя: использовать существующие документы `costs` с явной меткой `managementTax: true` и неизменяемым смыслом «начисление для ОПиУ». Их месяц задаётся датой конца месяца; сумма может быть нулевой, но не отрицательной. АИР-КЛИМАТ — УСН, АРБАТ.ГК — прибыль. Документ-основание обязателен. Сумма относится ниже EBITDA, не становится задолженностью поставщику или подтверждённым налоговым обязательством, не попадает в налоговые вычеты. Это позволяет использовать существующие серверные блокировки `costs.date`, авторство и CAS без параллельного хранилища.

Альтернативы: отдельная коллекция дала бы изоляцию, но потребовала бы нового серверного жизненного цикла; использование `taxObligationEvents` смешало бы предварительную оценку прибыли и подтверждённый долг. Поэтому сохраняются три самостоятельных слоя: расчёт налогов / месячный расход для ОПиУ / подтверждённые обязательства и уплата.

Вкладка ОПиУ в налоговом разделе: три месяца выбранного квартала, организация, налог, начисление, документ. Редактирование месяца обновляет существующий документ по стабильному id. Корректировка имеет предварительный просмотр; итог в копейках распределяется по текущим положительным суммам, без выдумывания базы при нулевой сумме. Ошибки/дубли блокируют корректировку; организация не смешивается. Сохранение проверяет исходный costs-снимок до и после ожидания серверной проверки всех затронутых месяцев. Неактивированная роль только читает; изменения разрешены admin/accountant как в действующем налоговом регистре.

Числовой приёмочный пример: 100.00 / 200.00 / 300.00 -> квартальный итог 500.00 даёт 83.33 / 166.67 / 250.00, сумма ровно 500.00; прежние начисления заменяются, а не суммируются повторно. Прибыль уменьшается, EBITDA и деньги не меняются. Вычетов НДС и долга поставщику не возникает. Записи другого квартала/организации не меняются.
