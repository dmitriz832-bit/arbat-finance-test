## Диагностика

Приложение остаётся статическим JavaScript-приложением на GitHub Pages. `app/telemetry.js` загружается асинхронно, получает отдельную runtime-конфигурацию и асинхронно подключает локальную копию SDK. Финансовое ядро, база и авторизация не передаются PostHog.

| Событие | Разрешённые свойства | Что означает |
|---|---|---|
| `arbat_app_loaded` | нет | SDK загрузился и адаптер начал работу; не доказательство успешного входа или полной загрузки базы |
| `arbat_navigation` | `section` из списка разделов | Переход в раздел без URL, идентификаторов и фильтров |
| `arbat_runtime_error` | `code` из списка классов | Класс ошибки без сообщения, stack trace и имени документа |
| `arbat_sync_result` | `status`: success / retry / failed | Сохранение общей базы, повтор после конфликта либо остановка синхронизации |

Это не подсчёт сотрудников, документов или полноты финансового учёта. Одна запись нескольких документов может давать одно событие синхронизации. Повтор одного класса ошибки подавляется в пределах загрузки страницы. Максимум 100 событий адаптера за загрузку страницы; очередь до готовности SDK ограничена 20 событиями. Адаптер загружается асинхронно и не задерживает разбор страницы; ошибки до его запуска могут быть пропущены. Из-за ограничений, блокировщиков и отсутствия сети сводка не является полным журналом аудита.

Фильтр `before_send` заново собирает весь пакет после обогащения SDK: пропускает только четыре события, перечислимые свойства, случайный идентификатор текущей страницы, публичный ключ проекта, время и флаги отключения профиля/геолокации. Автоматические поля URL, referrer, user agent, `$set` и `$set_once` исключаются. SDK добавляет собственный UUID события и время отправки.

Не вызывается `identify`; ID сотрудников не отправляются. Состояние аналитики хранится только в памяти страницы. Запись сессий, автосбор кликов, форм, страницы, исключений, консоли, производительности, опросы, feature flags и внешние модули SDK отключены. Серверный проект также отключает автосбор, запись, консоль и performance; удаление IP включено, часовой пояс Asia/Tomsk.

Запуск разрешён только для origin/path из конфигурации; локальные тесты и копии сайта не отправляют события. Do Not Track и Global Privacy Control отключают инициализацию. Сбой конфигурации, SDK или отправки не мешает работе приложения; `reportSync` дополнительно изолирован от ошибок диагностики.

## Конфигурация и обновление

`app/telemetry-config.json` — публикуемая runtime-конфигурация статического сайта, а не секрет. В ней только публичный ingestion token `phc_…`, регион, разрешённый origin/path и переключатель. Персональные API-ключи и Supabase service role здесь недопустимы.

Исходные значения задаются через `.env.local` (исключён из git), имена есть в `.env.example`:

```bash
npm ci --ignore-scripts
npm run build:telemetry
```

Генератор проверяет конфигурацию, копирует закреплённый lock-файлом SDK `array.no-external.js` и MIT-лицензию в `app/vendor/`. Сгенерированные публичные файлы версионируются: Pages обслуживает `main` непосредственно, без серверных переменных окружения. CI сверяет SDK с установленным пакетом. При обновлении зависимости необходимо повторить генерацию и браузерную проверку сетевых пакетов.

Для отключения сбора: установить `enabled: false` в runtime JSON и опубликовать. Отключение действует после перезагрузки открытых страниц. Если меняется домен приложения, одновременно обновить origin/path; иначе аналитика намеренно не запустится.

Документация SDK: https://posthog.com/docs/libraries/js/config

## Проверки

```bash
node --test tests/*.cjs
node --test e2e/telemetry.cjs
git diff --check
```

Браузерный сценарий использует настоящий закреплённый SDK, перехватывает транспорт и проверяет отсутствие данных документов, учёт ошибок между запуском адаптера и готовностью SDK, отсутствие блокировки страницы при зависшем запросе адаптера, ограничения отправки, отсутствие cookies/localStorage аналитики, DNT и работу формы при недоступности конфигурации. Тесты не посылают данные в рабочий PostHog. В среде без штатного Chromium можно задать `ARBAT_BROWSER=chromium ARBAT_CHROMIUM_PATH=/path/to/chromium`; CI использует Chromium и WebKit из образа Playwright.

Сбор событий не создаёт автоматических уведомлений или постоянного наблюдения со стороны ассистента. Встроенная связка GitHub ↔ Linear через OAuth не устанавливалась: проект содержит прямые ссылки, задачи обновляются через подключённый плагин.
